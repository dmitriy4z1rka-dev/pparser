# Лиды из Яндекс.Карт и 2ГИС в EspoCRM

Одна связка для сбора компаний и дальнейшей работы с ними:

```text
Панель сбора :8090 → очередь заданий → Яндекс / 2ГИС
                                         ↓
                              SQLite: компании и прогресс
                                         ↓
                                  REST API EspoCRM
                                         ↓
                             Лиды и задачи менеджера :8080
```

В EspoCRM оставлены разделы **Лиды**, **Задачи** и **Сбор компаний**. Карточка лида содержит компанию, телефоны, email, сайт, признак наличия сайта, адрес, категорию, соцсети, статус и заметки. Вход, профиль, выход, ответственные и группы убраны из рабочего интерфейса. Базовые модули EspoCRM физически не удалены: это упрощение рабочего пространства, а не переписывание PHP-платформы.

## Запуск

Нужны Docker Engine с работающим демоном, Docker Compose и доступ в интернет для загрузки образов и зависимостей. Хостовому пользователю нужен доступ к Docker. Python 3.10+ нужен только для подготовки конфигурации; PHP и браузеры на хосте не нужны.

Проверьте `docker ps`. Если получаете `permission denied` для `/var/run/docker.sock`, добавьте пользователя в группу Docker: `sudo usermod -aG docker "$USER"`, затем войдите в систему заново. Для текущего терминала можно открыть оболочку `newgrp docker` и выполнять команды внутри неё. Права группы Docker дают административный доступ к машине.

В этой папке:

```bash
python3 scripts/setup.py
docker compose up -d --build
```

Первый запуск скачивает EspoCRM 10.0.11, MariaDB, Python и Chromium. Затем автоматически устанавливает CRM, применяет поля и интерфейс, создаёт отдельного API-пользователя для импорта и запускает панель сбора.

* Панель: <http://localhost:8090>.
* CRM: <http://localhost:8080/#Lead>.
* CRM и панель открываются сразу, без регистрации, логина и пароля. База одна для всех локальных сессий браузера.
* `scripts/setup.py` создаёт служебные секреты и `.env` с правами `0600`. Повторный запуск не меняет существующие секреты; вводить их в интерфейсе не требуется.

Для необязательного получения дат из Places API добавьте демо- или API-ключ 2ГИС в локальный `.env` как `DGIS_API_KEY=...`, затем перезапустите сборщик: `docker compose up -d --build collectors`. Не отправляйте ключ в чат и не добавляйте его в git. Без ключа обычный браузерный сбор работает как прежде.

Это локальное рабочее пространство: порты опубликованы только на `127.0.0.1`, запросы с посторонними Host/Origin отклоняются. Внутри EspoCRM остаётся служебная учётная запись, необходимая её движку; она автоматически используется сервером и не разделяет данные между людьми. Парсеры используют отдельный служебный API-ключ с ограниченными правами. Пользовательских аккаунтов и назначения задач в рабочем процессе нет.

Проверить запуск:

```bash
docker compose ps
docker compose logs --tail=100 crm-setup collectors
```

Если изменяли файлы кастомизации:

```bash
docker compose up -d --build espocrm
docker compose run --rm crm-setup
docker compose up -d collectors crm-daemon
```

Секреты установщика применяются к новой базе. Для существующей CRM изменение `ADMIN_PASSWORD` в `.env` не заменяет внутренний пароль уже созданной служебной учётной записи. Не меняйте его отдельно от базы: сервер использует эти реквизиты для автоматического открытия рабочего пространства.

## Работа

1. Откройте панель сбора, выберите источник, город, категорию и лимит. Для Яндекса укажите `Москва`; для 2ГИС — адресный идентификатор города, например `moscow`, `spb` или `kazan`. Вместо поиска можно передать готовую HTTPS-ссылку.
2. Запустите сбор. Задания выполняются последовательно одним браузером, результаты сохраняются по мере получения.
3. После завершения, ошибки или остановки задания найденные компании отправляются в CRM. Неотправленные лиды повторно передаются автоматически, пока работает панель. Кнопка повторной отправки доступна отдельно.
4. При ограничении доступа задание останавливается с понятной причиной. После восстановления доступа нажмите **Продолжить**. Для Яндекса сохраняются ячейки сетки; для 2ГИС повторно обходятся страницы списка, уже собранные карточки этого задания пропускаются.
5. Откройте CRM, меняйте статус (`Новый → В работе → Успешно / Позже / Отказ`), ведите заметки и создавайте задачи.

**«Сайт не указан»** означает, что в полученных карточках нет ссылки на собственный сайт. Это не утверждение, что сайта у компании не существует. Соцсети и мессенджеры хранятся отдельно. Телефоны и почта собираются в доступном объёме; наличие email у каждого лида не гарантируется.

Если настроен `DGIS_API_KEY`, после сбора 2ГИС программа запрашивает `items.dates.created_at` у Places API по ID филиалов пачками до 100. В CRM это поле называется **«Внесена в базу 2ГИС»**. Дата необязательна: при отсутствии поля, отказе API или исчерпании лимита карточки сохраняются и синхронизируются без неё. Это дата каталога 2ГИС, не подтверждённая дата открытия точки или первого появления на карте. Для работы API нужны доступ Places и подходящие условия ключа; демо-ключ имеет ограниченный месячный лимит.

Телефоны нормализуются; повторный ID одного источника обновляет существующую компанию. Между источниками компании объединяются при совпадении города, адреса и названия либо телефона. Один телефон или домен без адреса недостаточен: филиалы остаются отдельными. Разные написания адреса могут оставить дубли — автоматическое объединение намеренно осторожное.

Заметки, статус и существующие флаги отказа от контактов при импорте сохраняются. Обычные поля CRM заполняются, если они пусты; контакты дополняются. Положительные сведения о сайте и ранее собранные контакты сохраняются при получении неполной карточки. Устаревший контакт удаляется вручную в CRM; повторный сбор может добавить его снова, если он по-прежнему опубликован на картах.

Если CRM отклоняет запись при создании или обновлении с HTTP 400/409/422, она остаётся в очереди с ошибкой, а остальные компании продолжают отправляться. При ошибке доступа, сетевом сбое или отказе сервера пакет останавливается до следующей попытки.

## Консоль и старые выгрузки

В Docker уже установлены зависимости:

```bash
docker compose exec collectors python -m leadgen collect yandex "Москва" "стоматология" --limit 50
docker compose exec collectors python -m leadgen collect 2gis moscow "стоматология" --limit 50 --delay 3
docker compose exec collectors python -m leadgen status
docker compose exec collectors python -m leadgen sync
docker compose exec collectors python -m leadgen resume ID_ЗАДАНИЯ
```

Панель должна быть единственным запускателем сбора при обычной работе. Консольные команды полезны для диагностики; не запускайте одновременно несколько сборов или импортов в одну базу.

Без Docker для Python-части:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
set -a
. ./.env
set +a
export ESPO_URL=http://localhost:8080
.venv/bin/python -m leadgen serve
```

CRM при этом может продолжать работать в Docker. Для отдельной PHP-установки нужны custom-слой и файлы `client/custom`; серверу передаются внутренние реквизиты установки `ESPOCRM_ADMIN_USERNAME`/`ESPOCRM_ADMIN_PASSWORD`. В каталоге CRM выполните `php command.php clear-cache`, `php command.php rebuild`, `php command.php leadgen-setup`, передав окружение `ESPO_API_KEY` и `LEADGEN_PUBLIC_URL`. Для действующей CRM используйте отдельную копию с резервной копией её настроек: setup меняет общую навигацию и поля Lead/Task.

Импорт прежних выгрузок с локального диска:

```bash
.venv/bin/python -m leadgen import-file yandex ./result.csv --city "Москва"
.venv/bin/python -m leadgen import-file 2gis ./result.json --city "Москва"
```

Поддерживаются CSV исходного Яндекс-парсера и JSON исходного 2ГИС-парсера (массив карточек или API-документов). Результат сначала сохраняется локально, затем отправляется в CRM. Если ключ или CRM недоступны, данные остаются для команды `sync`.

## Хранение

Compose использует отдельные постоянные тома: MariaDB, данные и кастомизации CRM, данные парсеров. В томе `collector-data` находятся `leads.sqlite3`, `checkpoints/*.json` и `logs/*.log`. В локальном режиме это каталог `var/`.

Для восстановления всей связки сохраняйте оба хранилища: базу и файлы CRM, а также SQLite парсеров. Идентификаторы очереди связывают локальные компании с CRM. Обычный `docker compose down` сохраняет тома.

Статусы, заметки, задачи, собранные компании и история заданий сохраняются на диске, независимо от cookies, профиля браузера и открытого чата. Закрытие браузера, новая сессия или перезапуск сервисов не очищают состояние. Команда `docker compose down -v` удаляет тома вместе с данными — для обычной остановки её не используйте.

## Проверки и ограничения

```bash
python3 -m unittest discover -s tests -v
docker compose config --quiet
```

Проверка установленной CRM на синтетических компаниях (после успешного запуска сервисов):

```bash
docker compose exec -T collectors python - < scripts/check_crm.py
```

Она обращается к настоящему API: проверяет создание и повторный импорт, объединение источников, отдельные филиалы, сохранение статуса/заметок/ответственного/opt-out и ограничения роли интеграции. Использует временную SQLite-базу и удаляет созданные лиды через администратора; штатная очередь сбора не меняется. Если тест прерван принудительно, тестовые лиды можно найти по имени `CRM test …`.

Браузерная проверка открытия без входа, списка, создания карточки, заметок и повторного открытия в новой сессии без cookies:

```bash
docker compose exec -T collectors python - < scripts/check_ui.py
```

Снимки сохраняются в `/data/test-artifacts` внутри сборщика. Синтетическая карточка удаляется после проверки.

Проверка сохранения состояния при перезапуске всех сервисов, включая MariaDB, запускается на хосте с доступом к Docker:

```bash
python3 scripts/check_persistence.py
```

Она создаёт тестовую компанию и задачу, перезапускает связку без удаления томов, проверяет их поля, существующие лиды и состояние очереди, затем удаляет тестовые записи. Запускайте после завершения текущего сбора.

Тесты проверяют объединение компаний и сохранение филиалов, все контакты 2ГИС, устойчивость очереди к перезапуску, импорт после потери ответа CRM, сохранение статусов/заметок/opt-out и восстановление сетки после ошибок. Контракт REST API проверяется через тестовый HTTP-транспорт; отдельная проверка реального TCP-соединения пропускается, когда среда запрещает сокеты.
