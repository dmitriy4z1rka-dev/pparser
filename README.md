# Локальная CRM для лидов из Яндекс Карт и 2ГИС

Приложение собирает карточки организаций из Яндекс Карт и 2ГИС, сохраняет результаты локально и передаёт компании в EspoCRM. Оно рассчитано на одного локального пользователя: регистрация, разделение записей по пользователям и назначение ответственных в рабочем процессе не используются.

```text
Браузерная панель :8090
        │ задания и управление сбором
        ▼
Парсеры карт ──► SQLite: компании, источники, очередь и прогресс
                              │
                              ▼
                     EspoCRM REST API :8080
                     MariaDB: лиды и задачи
```

## Быстрый запуск

Требуются Docker Engine с запущенным демоном, Docker Compose v2, Python 3.10+ и доступ к интернету для загрузки образов и зависимостей. На хосте не нужны PHP, Node.js и установленный Chromium.

```bash
git clone <URL-репозитория>
cd <каталог-репозитория>
python3 scripts/setup.py
docker compose up -d --build
```

При первом запуске Docker скачает EspoCRM, MariaDB и Python-образ с Chromium. Compose установит CRM, применит локальные настройки и поля, создаст ограниченную API-учётку для импорта и запустит сборщик.

- Панель сбора: <http://localhost:8090>
- CRM: <http://localhost:8080/#Lead>

Оба адреса доступны локально без входа. Порты привязаны к `127.0.0.1`; **не публикуйте их в интернет и не меняйте привязку на `0.0.0.0` без отдельной настройки аутентификации и сетевой защиты**.

`scripts/setup.py` генерирует случайные секреты в `.env` с правами `0600`. Повторный запуск не перезаписывает существующие пароли. Файл `.env` содержит секреты и исключён из Git. Шаблон параметров находится в [.env.example](.env.example).

Если Docker сообщает `permission denied` для сокета, сначала настройте доступ пользователя к Docker по инструкции для вашей ОС. Членство в группе `docker` даёт широкие права на машине.

## Как работает программа

### Сбор и сохранение

1. В панели выберите источник, город, запрос, лимит и паузу. Для Яндекса указывайте название города, например `Москва`; для 2ГИС — slug города, например `moscow`, `spb` или `kazan`. Можно указать готовую HTTPS-ссылку на поиск подходящего сервиса.
2. Сборщик выполняет задания по очереди. Яндекс использует Chromium и при включённом обходе по сетке делит область поиска на ячейки. 2ГИС обходит результаты поиска и открывает карточки организаций.
3. Каждая найденная карточка сохраняется в SQLite до следующего сетевого шага. Там же хранятся задания, уже обработанные ID и состояние синхронизации. Перезапуск браузера или контейнера не очищает базу.
4. После сбора данные отправляются в EspoCRM. Если CRM или сеть временно недоступны, локальные записи остаются в очереди; сборщик повторяет отправку автоматически, пока работает.

Источники не гарантируют полный список организаций города. На выдачу влияют полнота каталога, лимиты и сортировка самих карт, ошибки сети, CAPTCHA и другие ограничения. Увеличение лимита не заставляет сервис карт показать все компании.

### Нормализация и объединение компаний

В базе SQLite каждая исходная карточка остаётся отдельным наблюдением своего источника. Сводная компания объединяет контакты и ссылки, но сохраняет ссылки на карточки Яндекса и 2ГИС.

Карточки разных источников объединяются только при совпадении города и адреса филиала, а также названия или телефона. Совпадения только по общему телефону или сайту недостаточно: это сохраняет разные филиалы сети. При неоднозначном адресе могут остаться дубли; алгоритм намеренно предпочитает их ошибочному объединению.

Повторная карточка с тем же ID обновляет наблюдение. Неполная карточка не стирает ранее собранные телефоны, сайты, соцсети и дату из каталога. Кириллические домены сайтов переводятся в ASCII/punycode перед отправкой в CRM.

### Что передаётся в CRM

Каждой локальной компании присваивается стабильный `cLeadgenId`. По нему импорт обновляет существующий лид, а не создаёт дубликат. Новые компании получают статус **Новый**.

В CRM доступны название, телефон, email, сайт, город и адрес, категория, соцсети и ссылки на карты. Оценка точки и число оценок хранятся отдельно для каждого источника: **Яндекс.Карты** и **2ГИС**. Эти значения не усредняются. Если источник не вернул метрику, пустое значение не затирает ранее полученное.

Для 2ГИС можно дополнительно запрашивать `dates.created_at` через Places API. Это дата внесения карточки в каталог, а не подтверждённая дата открытия или первого появления точки на карте. Запросы выполняются пачками до 100 ID; доступ и квота зависят от выданного ключа и условий 2ГИС.

Статусы лида: **Новый**, **В работе**, **Успешно**, **Позже**, **Отказ**. В списке CRM для них есть кнопки со счётчиками. Поиск и дополнительные фильтры сохраняются. Заметки менеджера находятся в боковой части карточки: Enter сохраняет поле, Shift+Enter вставляет новую строку заметки. Отдельный раздел **Задачи** оставлен.

Импорт не меняет статус, заметки и другие рабочие решения менеджера. Обычные поля лида заполняются, если они пусты; контакты дополняются. Сведения об источниках и метриках обновляются при повторной синхронизации.

### Даты 2ГИС (необязательно)

Чтобы включить получение даты из Places API, добавьте ключ в локальный `.env`:

```dotenv
DGIS_API_KEY=ваш_ключ
```

Затем пересоздайте сборщик:

```bash
docker compose up -d --build collectors
```

Без ключа сбор работает обычно, но дата не запрашивается. Если API недоступно, вернуло ошибку или квота исчерпана, карточки всё равно сохраняются и отправляются без даты. Не вставляйте ключ в README, исходный код, issue или коммит.

## Сервисы и настройки

| Сервис | Назначение | Порт |
|---|---|---:|
| `collectors` | Панель, браузерные парсеры, очередь и SQLite | 8090 |
| `espocrm` | Интерфейс CRM и REST API | 8080 |
| `db` | Постоянная база CRM MariaDB | внутренний |
| `crm-daemon` | Фоновые задачи EspoCRM | внутренний |
| `crm-setup` | Однократное применение локальной настройки CRM | внутренний |

Основные параметры Compose задаются через `.env`: пароли БД, пароль внутренней установки EspoCRM, API-ключ импорта и локальные URL. `DGIS_API_KEY` необязателен. Не добавляйте реальные секреты в `.env.example`.

Полезные команды:

```bash
docker compose ps
docker compose logs -f collectors
docker compose logs --tail=100 espocrm
docker compose stop                 # остановить без удаления данных
docker compose start                # запустить снова
docker compose down                 # удалить контейнеры, тома останутся
```

После изменения файлов CRM-кастомизации пересоберите CRM и запустите настройку:

```bash
docker compose up -d --build espocrm
docker compose run --rm crm-setup
docker compose up -d collectors crm-daemon
```

## Где хранятся данные

Compose создаёт отдельные Docker volumes:

- `db` — база MariaDB с лидами и задачами;
- `crm-data`, `crm-custom`, `crm-client-custom` — состояние и настройки EspoCRM;
- `collector-data` — `leads.sqlite3`, контрольные точки и логи сбора.

Без Docker каталог данных задаётся `LEADGEN_DATA`; по умолчанию это `./var`. В контейнере это `/data`.

Сохраняйте резервные копии **и** базы MariaDB, **и** томов CRM/сборщика. Для штатной остановки используйте `docker compose stop` или `docker compose down`. Команда `docker compose down -v` удаляет volumes вместе с рабочими данными.

## Проверки

Python-тесты логики и интеграционного контракта:

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q leadgen scripts tests
docker compose config --quiet
```

После запуска сервисов можно выполнить проверки настоящей CRM и браузерного интерфейса:

```bash
docker compose exec -T collectors python - < scripts/check_crm.py
docker compose exec -T collectors python - < scripts/check_ui.py
```

Они создают временные синтетические лиды и удаляют их после проверки. UI-сценарий проверяет кнопки статусов, сохранение по Enter, перенос строки по Shift+Enter и доступность заметки после перезагрузки и в новой сессии.

Проверка сохранности после полного перезапуска, включая MariaDB:

```bash
python3 scripts/check_persistence.py
```

Она перезапускает Compose-сервисы и не должна запускаться во время активного сбора. Скрипт создаёт и удаляет тестовые CRM-записи; volumes не удаляются.

Сбор реальных карточек ограничениями каталога и проверкой CAPTCHA не покрывается. Подробные результаты текущих проверок смотрите в [docs/TESTING.md](docs/TESTING.md).

## Консольные команды

Команды запускаются внутри контейнера сборщика и используют ту же базу, что и панель. Не запускайте параллельно несколько сборов в одну базу.

```bash
docker compose exec collectors python -m leadgen status
docker compose exec collectors python -m leadgen collect yandex "Москва" "стоматология" --limit 50
docker compose exec collectors python -m leadgen collect 2gis moscow "стоматология" --limit 50 --delay 3
docker compose exec collectors python -m leadgen sync
docker compose exec collectors python -m leadgen resume ID_ЗАДАНИЯ
```

Импорт старых выгрузок:

```bash
docker compose cp result.csv collectors:/tmp/result.csv
docker compose exec collectors python -m leadgen import-file yandex /tmp/result.csv --city "Москва"
docker compose cp result.json collectors:/tmp/result.json
docker compose exec collectors python -m leadgen import-file 2gis /tmp/result.json --city "Москва"
```

Для локального запуска Python-сборщика без Docker см. переменные и зависимости в [Dockerfile](Dockerfile) и [requirements.txt](requirements.txt); для отправки результатов всё равно нужна доступная EspoCRM и `ESPO_API_KEY`.

## GitHub и сторонний код

Парсеры карт и CRM-кастомизации лежат в `vendor/` как обычные файлы репозитория. Поэтому для сборки не нужны незадокументированные git-ссылки или отдельная инициализация submodule. Исходные страницы проектов и их файлы лицензий сохранены рядом с кодом, где они были доступны.

Перед публикацией проверьте `git status` и убедитесь, что в коммит не попали `.env`, базы, логи, профили браузера, скриншоты и тестовые выгрузки. `.gitignore` и `.dockerignore` исключают локальные рабочие данные. Не добавляйте секреты и реальные данные компаний в issue и примеры.

Корневой проект пока не задаёт собственную лицензию. В `vendor/parser-2gis-new/LICENSE` сохранена LGPLv3 стороннего парсера 2ГИС; для других исходников проверьте сведения об авторе и лицензии в сопровождающих файлах до публичного распространения.
