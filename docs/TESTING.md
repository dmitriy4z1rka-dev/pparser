# Проверка связки CRM, 2026-11-02

Проверена отдельная установка Compose-проекта `map-leads`: EspoCRM 10.0.11, MariaDB 11.4, демон задач и панель сбора. Ранее работавшие контейнеры проекта `parser-crm` остановлены по поручению пользователя, их тома сохранены. Для доступа к Docker пользователь `arch` добавлен в группу `docker`; перезапуск системы не понадобился, команды выполнялись через `newgrp docker`.

## Исправления по результатам проверки

1. Healthcheck проверял `isInstalled` в неверном файле. Теперь используется штатная CLI-команда EspoCRM, зависимые сервисы запускаются после установки.
2. Сервер отбрасывал ID и ссылки интеграции из-за `readOnly`. Используется `clientReadOnly`, запись через API и запрет редактирования в интерфейсе совместимы.
3. API игнорировал строковый `where`, из-за чего второй филиал мог обновлять первый. Используется JSON `searchParams`, клиент проверяет совпадение `cLeadgenId` перед обновлением. Исправление подтверждено регрессионным тестом, сначала воспроизводившим ошибку, и настоящей CRM.
4. Ошибка в одной компании останавливала пакет. HTTP 400/409/422 на запись оставляет её в очереди и позволяет отправлять следующие компании; общий отказ, ошибки поиска и доступа останавливают пакет. Оба варианта проверены тестами.
5. По уточнению пользователя интерфейс переведён в общее локальное пространство: без регистрации/входа, профиля, выхода, ответственных и групп. Внутренний служебный контекст EspoCRM сохранён, разделения данных по пользователям нет. Существующие записи не удалялись.

## Повторение

Из корня проекта с работающими сервисами:

```bash
python3 -m unittest discover -s tests -v
docker compose config --quiet
docker compose exec -T collectors python - < scripts/check_crm.py
docker compose exec -T collectors python - < scripts/check_ui.py
python3 scripts/check_persistence.py
docker compose ps -a
```

Пользовательские реквизиты для проверок не требуются; служебный API-ключ парсеров берётся из окружения контейнера. Скрипты создают только синтетические записи со случайным именем и удаляют их после проверки. Браузерные снимки находятся в `/data/test-artifacts` сборщика.

## Быстрый ручной проход

1. Открыть [CRM](http://localhost:8080/#Lead). Она открывается сразу, без логина и пароля.
2. Открыть один из четырёх собранных лидов: проверить телефон, сайт, адрес и переход на Яндекс или 2ГИС.
3. Изменить статус и заметку, сохранить и обновить страницу. Открыть ту же карточку в новом приватном окне: состояние должно сохраниться.
4. Создать задачу в карточке, указать срок, затем завершить её в разделе «Задачи». Ответственный не требуется.
5. В [панели сбора](http://localhost:8090) без входа проверить два завершённых задания и нулевую очередь отправки.
6. При желании создать свою компанию вручную и проверить фильтр по наличию сайта.

Небольшая живая выборка подтверждает работу связки на момент проверки. Полный обход города, устойчивость длительного сбора и ручное восстановление после настоящей CAPTCHA не проверялись. Перезапуск worker и восстановление checkpoint покрыты модульными проверками с имитацией браузера.
